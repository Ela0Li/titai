# 知识包 deck.json 字段速查（协议 v1.7，结构 schema 1）

一个知识包就是一个 JSON 对象。下面的表按「从外到内」排列，最后一列写的是**校验器怎么判**（错误码来自 `scripts/validate-deck.js`）。

字段的类型与上限以 `assets/schema/deck.schema.json` 为准，那个文件是权威定义；本页补的是「语义」与「写成什么样才对」。两者并不完全重叠——**长度类上限（标题字数、tags 单条字数）脚本不查**，只查结构与引用，见 `references/validation.md` 的「脚本不查什么」。

## 顶层

| 字段 | 必填 | 类型与上限 | 说明 |
|---|---|---|---|
| `schema` | ✓ | 整数，恒为 `1` | 破坏性变更才 +1；写别的值直接 `E_SCHEMA` |
| `id` | ✓ | `^[a-z0-9][a-z0-9-]{1,40}$` | 包的标识。**导入同 id 会覆盖**，进度按 id 存 |
| `title` | ✓ | ≤ 120 字 | 列表页与顶部标题，如「机器学习入门 · 从数据到上线」 |
| `subtitle` | | ≤ 200 字 | 一句话说明这个包的范围 |
| `accent` | | `#RRGGBB` | 主题色，缺省用引擎的蓝 |
| `terms` | | `{group, check, qa}` 各 ≤ 8 字 | 改界面称呼，缺省「模块 / 知识点 / 问答」。**建议三个一起写**：只改一个会让界面半中半英 |
| `updatedAt` | | ISO 时间 | 只作记录，引擎不依赖 |
| `deps` | | `[{id, title}]` | 本包引用了哪些包（仅提示，不强制安装） |
| `groups` | ✓ | 非空数组 | 见下 |
| `qas` | ✓ | 非空数组 | 见下 |

`additionalProperties` 是允许的：多写的字段不会报错，但引擎也不会显示，别指望它。

## group（模块）

| 字段 | 必填 | 类型与上限 | 说明 |
|---|---|---|---|
| `id` | ✓ | `^[A-Za-z][A-Za-z0-9_-]{0,15}$` | 如 `m1`。**所有知识点与问答都挂在这个前缀下** |
| `title` | ✓ | ≤ 120 字 | 写作「模块一 · C++ 语言机制」：序号给人看，冒号后是内容 |
| `short` | | ≤ 60 字 | chip 上的短名（顶部计划条空间很窄） |
| `priority` | ✓ | `P0`/`P1`/`P2` | P0 = 必须会，P1 = 应该会，P2 = 加分 |
| `stage` | ✓ | 1–4 | 学习阶段：1 基础 → 4 综合。同包内 stage 是单调的 |
| `signal` | | ≤ 400 字 | 「这组在考什么」的一句话，缺省只警告但要写 |
| `keypoints` | | 字符串数组 | 这组的核心结论，3–5 条，每条一个判断 |
| `traps` | | 字符串数组 | 常见错法/误解，2–4 条。**这是这个 App 与普通题库的主要差别** |
| `checks` | ✓ | 非空数组 | 见下 |

`keypoints` 与 `traps` 会参与搜索（权重低于知识点正文），所以写成能独立读懂的一句话，不要写「见上」。

## check（知识点）

| 字段 | 必填 | 类型与上限 | 说明 |
|---|---|---|---|
| `id` | ✓ | `^[A-Za-z][A-Za-z0-9_-]*\.[0-9]+$` | **必须**是 `groupId.数字`，如 `m1.3`，否则 `E_CHECK_PREFIX` |
| `text` | ✓ | 4–300 字，实际 20–60 | 一句话的知识点，陈述句，不是问句 |
| `lvl` | ✓ | `P0`/`P1`/`P2` | 与所属模块可以不同（模块 P1 里也有 P0 知识点） |
| `hint` | | 6–60 字，不换行 | 「及格线」：说到哪几条算过。只写判据，不写答案 |
| `seeAlso` | | ≤ 2 条，不重复 | 「顺带看」的**问答** id（不是知识点），可以是跨包 `deck#q.x` |

知识点的 `text` 是扫读单位：用户在列表页一屏看十几条，所以它必须短且自足。写不下就说明这是两条知识点。

## qa（问答）

| 字段 | 必填 | 类型与上限 | 说明 |
|---|---|---|---|
| `id` | ✓ | `^q\.[A-Za-z0-9_]+(\.[A-Za-z0-9_]+)*$` | 建议 `q.<模块>.<短名>`，如 `q.m2.noise`；短名用英文，别用中文 |
| `m` | ✓ | 某个 group 的 id | 主归属模块，决定它在哪个模块下计数 |
| `lvl` | ✓ | `P0`/`P1`/`P2` | 难度/重要度 |
| `layer` | ✓ | 1–4 | 认知层级：1 事实 → 2 机制 → 3 边界与权衡 → 4 综合设计 |
| `q` | ✓ | 6–300 字，以 `？` 或 `。` 结尾 | 问句本身。多个小问可以合成一条，但别超过三个 |
| `tags` | | ≤ 6 个，每个 ≤ 24 字 | 搜索用，写名词（`噪声`、`fBm`），不要写「重要」 |
| `covers` | ✓ | 非空、不重复 | 覆盖的知识点 id（可以是跨包 `deck#m1.1`） |
| `next` | | ≤ 3 | 往下追问的问答 id；App 自动反向显示「被追问」 |
| `peer` | | ≤ 3 | 同级对比的问答 id；App 自动反向显示「被对比」 |
| `ans` | ✓ | 1–12 块 | 见下 |

`next`/`peer` 只写单向。两边都写会得到「互相被追问」，`W_CYCLE` 会提示你。

## ans（答案块）

| 字段 | 必填 | 类型与上限 | 说明 |
|---|---|---|---|
| `h` | | 1–24 字 | 自拟小标题，如「一句话」「关键差异」「坑」。不写就是普通段落 |
| `lvl` | | 1–3，缺省 1 | 标题层级。**不能跳级**（上一个是一级就不能直接来三级）；没有 `h` 时写 `lvl` 会报 `E_ANS_LVL` |
| `p` | ✓ | 8–1200 字 | 正文；即使配了 `list`，`p` 也要写引导句 |
| `list` | | 1–10 条，每条 2–200 字 | 要点列表。每条应能独立读懂，不要「同上」 |

块内不要写 HTML（`<b>`、`<br>` 等会被转义并报 `E_ANS_HTML`）。强调靠结构，不靠加粗。

## 公式写法

行内 `$…$`，独占一行用 `$$…$$`。支持 LaTeX 的一个子集：

- 上下标 `x_i`、`x^{2}`，`\frac{a}{b}`、`\sqrt{x}`、`\sum_{i}^{n}`、`\prod`、`\int`
- 希腊字母 `\alpha \beta \theta \lambda \sigma \Omega`
- `\text{中文}`、`\mathrm{d}` 保留正体
- 反引号里的内容不当公式：`` `cost` `` 原样显示

不要写 `\begin{aligned}`、`\matrix`、`\color` 这类未支持的宏——`W_MATH_CMD` 会提示，App 里会显示成原字符。括号不平衡会报 `E_MATH_BRACE`，`$` 落单报 `E_MATH_BALANCE`。

App 端公式依赖字体：模拟器（旧镜像）可能显示豆腐块，这是字体缺失不是语法错，真机上正常。

## 跨包引用

任何 `ref` 类型字段都可以写成 `deckId#localId`：

```json
{ "id": "q.m1.grad", "covers": ["m1.2", "ml-math#m2.4"] }
```

规则：

- `#` 前是包的 `id`（小写连字符），`#` 后是那个包里的本地 id
- 目标包**没装**时 App 显示为灰色不可点，装上后自动恢复
- 目标包已装但在**当前计划之外**时，点击会问「加入计划并跳转 / 先看看」
- 引用只在语法层校验，不强求目标包在本机（`check.js` 只能查本包）

## 最小可用示例

`assets/deck.template.json` 是一个 2 模块 / 5 知识点 / 4 问答、覆盖率 100%、零警告的完整包。复制它，替换 `id`、`title`、内容，就能开始写自己的。
